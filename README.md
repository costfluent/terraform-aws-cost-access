# terraform-aws-cost-access

Grants [Costfluent](https://costfluent.com) read-only access to one AWS account's cost data.

The module creates an IAM role that Costfluent assumes from its own account, proving intent with
the external ID your Costfluent connection page generates, and attaches a policy allowing Cost
Explorer reads and nothing else.

## Requirements

- Terraform >= 1.13
- Permission to create IAM roles and inline role policies in the target account.
- Cost Explorer enabled on the account. It is enabled from the payer account and can take up to
  24 hours to return data the first time.

## Usage

```hcl
provider "aws" {
  region = "us-east-1"
}

module "costfluent" {
  source  = "costfluent/cost-access/aws"
  version = "~> 1.0"

  costfluent_account_id = "123456789012"  # shown on the Costfluent connection page
  external_id           = "cf_abc123..."  # generated by Costfluent; do not invent one
}

output "costfluent_credentials" {
  value     = module.costfluent.credentials_json
  sensitive = true
}
```

Then:

```bash
terraform apply
terraform output -raw credentials_json | pbcopy
```

Paste into Costfluent → Providers → Add provider → Amazon Web Services.

## Inputs

| Name | Description | Type | Default |
|------|-------------|------|---------|
| `costfluent_account_id` | Costfluent's AWS account ID, trusted to assume the role. | `string` | required |
| `external_id` | External ID for the assume-role handshake, generated by Costfluent. | `string` | required |
| `role_name` | Name of the IAM role. | `string` | `"CostfluentBillingRole"` |
| `max_session_duration` | Maximum session lifetime in seconds, 3600–43200. | `number` | `3600` |
| `tags` | Tags applied to the IAM role. | `map(string)` | `{}` |

## Outputs

| Name | Sensitive | Description |
|------|-----------|-------------|
| `credentials` | yes | Map of `role_arn` and `external_id`. |
| `credentials_json` | yes | The same map as JSON, ready to paste into Costfluent. |
| `role_arn` | no | ARN of the role Costfluent assumes. |
| `account_id` | no | Account the role was created in, to confirm you targeted the right one. |

The credential field names are Costfluent's contract. Do not rename them on the way in.

## Permissions granted

Two read-only Cost Explorer operations, and nothing else:

| Action | Why |
|---|---|
| `ce:GetCostAndUsage` | Reads the cost and usage records Costfluent collects. |
| `ce:ListCostAllocationTags` | Reads the names of your active cost allocation tags. Returns tag keys only, never values or cost. |

Cost Explorer has no resource-level permissions, so the policy's resource is necessarily `*`. That
grants no access to any resource in the account — only to these two API calls.

Forecasting, dimension values and reservation or Savings Plans utilization are computed by
Costfluent from data it has already collected, not fetched from your account, so no permission for
them is requested.

The role is assumable only by the Costfluent account named in `costfluent_account_id`, and only
when the caller presents the matching external ID.

## Security

- Credential outputs are marked sensitive, so they stay out of CLI output and logs.
- Nothing here is a long-lived key. Costfluent holds only the role ARN and external ID, and every
  session it assumes is temporary and capped by `max_session_duration`.
- Removing the module with `terraform destroy` revokes Costfluent's access completely.
